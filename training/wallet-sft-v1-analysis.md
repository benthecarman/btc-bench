The wallet SFT pass worked as a specialization, but it is not an overall upgrade. Keep broad checkpoint 528 as the general checkpoint and retain wallet checkpoint 128 for further experiments. The original live server was restored; no production model was replaced.

Combining chat and submit results, wallet development accuracy rose from 0/80 to 52/80. The reserved check rose from 0/64 to 44/64. Within the reserved check, familiar patterns scored 26/32 and new compositions scored 18/32. These are repeated views of 16 scenarios, not 64 independent samples. The new compositions are absent from this run's training mix under normalized comparison; absence from all historical training has not been established. This remains a small synthetic test. It is clearly below the old benchmark ceiling.

The compound regression suites retained the same combined total, 144/192, with 11 gains and 11 losses. The observed human-v2 set fell from 104/320 to 79/320: 15 gains and 40 losses. Script writing fell from 81/240 to 69/240, and tree tasks from 23/80 to 10/80. In particular, submit tree accuracy fell from 16/40 to 5/40 with no new correct answers in that cell. Two submit generations reached the context limit and count as failures. All 720 new generations are accounted for.

Spot checks show both useful transfer and specific errors:

- In `wr1-owner-last-template`, both interfaces correctly use the owner at `@1` as the internal key and the backup at `@0` behind `older(720)`.
- In `wr1-age-and-height-template`, chat correctly combines output age and absolute height. Submit gives the same structure with one extra closing parenthesis, so it fails syntax validation.
- In `wr1-quorum-or-joint-template`, chat combines two alternative routes with AND, requiring both groups. Submit also uses invalid descriptor syntax. This is a remaining composition problem.
- In `wp-native-single-0-template`, chat invents `388(pk(@0/**))`; submit correctly returns `wpkh(@0/**)`. Native wrappers remain weak.
- In `wp-joint-councils-0`, both interfaces turn the second council's one-of-two approval into two-of-two approval, in both representations. Their policies and descriptors agree with each other but violate the request.
- A previously correct human-v2 recovery request now produces `tr(owner,{backup,older(1008)})`, with actual keys in place of the role names. This is invalid syntax, not merely a worse optimization score. Other lost tree answers mix high-level policy syntax into descriptors. The wallet gain does not transfer reliably across wording and answer contracts.

The training targets were checked before use: all 256 policies and their descriptor bodies pass typed contract checks, and all 1,024 actual trainer rows pass loss-mask checks without truncation. Nevertheless, the model does not always reproduce valid reasoning. Across its 144 wallet evaluation outputs, 99 explicitly stated policies match the requested contract; 28 do not match, nine are invalid, and eight are missing or ambiguous. Of the 96 correct final answers, 17 have a wrong or invalid explicitly stated policy. For example, `wp-recovery-time-1-template` in chat gives the correct independent recovery descriptor but writes `and(pk(@0),and(pk(@1),after(1924992000)))` as its policy. That expression requires both keys and a delay instead of providing independent owner and backup routes.

The separate body check found 13 correct final answers with invalid or semantically wrong stated bodies. It measures only explicitly marked, single-line body expressions, combines Taproot bodies with the reference internal key, and does not validate the model's choice of internal key. Missing expressions are unmeasured. The first extraction pass accidentally included a prose sentence after some body blocks; it is retained as `trace-audit-extraction-v1.json`. The corrected analysis is `trace-audit.json`. No final-answer grade, training data, or experiment setting changed.

The next experiment should address the observed regression before a long RL run. Use the parent as a control and test a smaller wallet update or stronger replay that covers freely worded script and descriptor requests. Add independently written requests that change which signatures are alternatives versus joint requirements, and paired requests that ask for raw script versus a descriptor. Keep all derivatives of each scenario in one split. Do not add these inspected reserved questions to training and continue calling them a final test.

A small RL reward-variation probe is now more useful than it was at the zero-score wallet baseline. Before wallet RL training, connect the wallet verifier to the RL reward path and verify end-to-end tool/reward behavior; the separate wallet CLI is not yet an RL reward-server case. Probe training questions with multiple samples and include earlier skills in the reward pool. A single-sample test score does not establish the amount of reward variation available to GRPO.
